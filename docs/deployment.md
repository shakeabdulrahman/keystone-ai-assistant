# Deploying Keystone for free (Render + Neon + Gemini)

About 30 minutes. Everything here uses free plans. Free-tier limits and model names change, so check each provider's pricing page on the day you deploy.

| Piece | Service | Free-tier behaviour to know |
| --- | --- | --- |
| API (Docker) | Render free web service | Sleeps after ~15 min idle; the first request then takes up to a minute |
| Database | Neon free Postgres (pgvector built in) | Suspends when idle and resumes in about a second |
| AI (chat + embeddings) | Gemini API with a Google AI Studio key | Requests per minute and per day are capped; **free-tier prompts may be used by Google to improve its products, so use demo data only** |
| Sign-in, push, App Check | Firebase Spark plan | Already set up in `docs/firebase-setup.md` |

Ollama can't run on a free server (a 7B model needs several GB of RAM), which is why production uses Gemini. Switching is configuration only: `LLM_PROVIDER=gemini`.

## 1. Database: Neon

1. Sign up at neon.tech and create a project (pick the region closest to your Render region, e.g. Frankfurt).
2. **Connection details → Connection string.** Turn **"Connection pooling" off** (the direct host, not `-pooler`). asyncpg uses prepared statements, which the pooler's transaction mode doesn't support.
3. Copy the string. It looks like `postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require`. Paste it as is: the backend converts it for asyncpg (`postgresql+asyncpg://…?ssl=require`).

pgvector is enabled by the first migration (`CREATE EXTENSION IF NOT EXISTS vector`).

## 2. AI: Gemini key

1. Open aistudio.google.com → **Get API key** → create a key.
2. Check the current free models at ai.google.dev/gemini-api/docs/models. Defaults: `GEMINI_MODEL=gemini-3.8-flash`, `GEMINI_EMBEDDING_MODEL=gemini-embedding-001` (768 dimensions requested, matching the vector column). If a model is retired, Google's error says which model replaces it (the server logs it as `gemini_error`). Update `GEMINI_MODEL` in `render.yaml` and push: Render syncs Blueprint values, so a change made only in the dashboard is overwritten on the next sync.

## 3. API: Render

1. Push the repository to GitHub.
2. Render dashboard → **New → Blueprint** → choose the repository. Render reads `render.yaml`.
3. Fill in the values it asks for (stored as secrets by Render, never in git):
   - `DATABASE_URL`: the Neon string
   - `GEMINI_API_KEY`
   - `FIREBASE_PROJECT_ID` (e.g. `keystone-12345`) and `FIREBASE_PROJECT_NUMBER` (Firebase console → Project settings → General)
4. **Push (optional):** service → **Environment → Secret Files → Add** `firebase-service-account.json` with the key's contents. Render mounts it at `/etc/secrets/firebase-service-account.json`, where `FCM_SERVICE_ACCOUNT_FILE` points.
5. Deploy. The container runs `start.sh`: migrations, then the knowledge-base load (embeddings via Gemini; unchanged documents are skipped on later starts), then the server on Render's `$PORT`.
6. `METRICS_TOKEN` was generated by Render; copy it from the Environment tab if you want to scrape `/metrics`.

## 4. Check it: smoke test

```bash
python3 scripts/smoke_test.py https://keystone-api.onrender.com
METRICS_TOKEN=… python3 scripts/smoke_test.py https://keystone-api.onrender.com
```

It checks liveness, readiness (database + pgvector), production mode, security headers, hidden API docs, refused anonymous and `dev:` tokens, and the metrics token. With `ID_TOKEN=<a Firebase ID token>` it also loads the home dashboard and asks one question.

## 5. The app: release build

In `mobile/local.properties` (not committed):

```properties
keystone.releaseApiBaseUrl=https://keystone-api.onrender.com
# Signing (create once: Build → Generate Signed App Bundle/APK → Create new…)
keystone.signing.storeFile=/Users/you/keys/keystone-release.jks
keystone.signing.storePassword=…
keystone.signing.keyAlias=keystone
keystone.signing.keyPassword=…
```

Then `./gradlew :androidApp:assembleRelease`. Keep the keystore and its passwords outside the repository and back them up: losing the key means you can't update the app in the Play Store. CI reads the same settings from environment variables (`KEYSTONE_SIGNING_*`, `KEYSTONE_RELEASE_API_BASE_URL`).

Add the **release** keystore's SHA-256 to the Firebase Android app (Project settings → your app → Add fingerprint): Play Integrity (App Check) needs it. Get it with `keytool -list -v -keystore keystone-release.jks -alias keystone`.

## 6. App Check: monitor, then enforce

1. Firebase console → **App Check** → register both Android apps: **Play Integrity** for `com.keystone.assistant`. For the debug app (`.debug`), registering any provider is enough, because debug builds use the debug provider.
2. **Debug token for the emulator:** run the debug app once, find `DebugAppCheckProvider` in Logcat ("Enter this debug secret into the allow list…"), then App Check → ⋮ on the debug app → **Manage debug tokens → Add**.
3. The deployment starts with `APP_CHECK_MODE=monitor`: requests without a valid token are logged (`app_check_failed`) but served. Watch the logs for a day of normal use.
4. When only real attacks would fail, set `APP_CHECK_MODE=enforce`. Calls without a valid token now get `403 app_check_failed`.

To restrict to specific app IDs, set `APP_CHECK_APP_IDS=1:123:android:abc,…` (Firebase app IDs).

## 7. Point the debug app at the cloud (optional)

`mobile/local.properties`: `keystone.apiBaseUrl=https://keystone-api.onrender.com`. HTTPS works without changing the debug network config.

## Operating it

- **Logs:** Render → Logs. JSON lines with `request_id`; no message content, tokens or keys are logged.
- **Rate limits** are in memory per instance. With one free instance that's exact; with several, move the limiter to Redis (the `RateLimiter` interface is ready for it).
- **Client IPs:** Render's proxy appends the caller's IP to `X-Forwarded-For`, so `TRUSTED_PROXY_HOPS=1`. The backend takes the IP that proxy added, never the client-written part of the header.
- **"Model is experiencing high demand" (503):** common on the free tier. The server retries twice (after 1 s and 3 s) before giving up, and then tries `GEMINI_FALLBACK_MODELS` in order. Set that in Render → Environment to one or two other models your key can use (list them with the `models` API call in the troubleshooting notes).
- **Gemini quota errors** reach the app as "The assistant is busy right now". Lower `RATE_CHAT_PER_MINUTE` if you keep hitting the free cap; title generation uses one extra call per new conversation (`TITLE_GENERATION_ENABLED=false` to save quota).
- **Rotating a secret:** change it in Render (Environment) and redeploy. For the Firebase key, create a new key, replace the secret file, deploy, then delete the old key in Google Cloud.
- **Cost guard:** nothing here takes a credit card except, optionally, Render. If a provider asks for one, the free plan is still enough.
